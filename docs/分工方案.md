# 主副模型分工方案

> 主模型：Kimi-K3.1-Pro ｜ 副模型：DeepSeek-V4.1-Flash
> 范围：DeepSeek Harness 一键更新器（`README.md` / `src/` 15 个模块 / `test/` 8 个文件 61 项 / `prototype.html`）
> 目标：完善为可公开发布的产品，兼容 Windows 与 macOS

---

## 1. 分工依据

两个模型都能当主模型，也都写得了代码。所以分工不按"谁强谁弱"切，按一条判据切：

> **这个任务需不需要"同时看很多文件、并替后面几步做决定"？**
> 需要 → 主模型；边界清楚、结果能被命令判定 → 副模型。

主模型的稀缺资源不是钱，是**上下文容量和判断准确率**。一次读 1169 行 README + 15 个模块 + 8 个测试文件还能保持一致性的，只有主模型；这类工作一旦拆给副模型，代价不是慢，是"每个模块一套自己的假设"。

副模型的优势是**单位任务成本低、来回快**。凡是能写清"改成什么样、怎么算改对了"的活，都该给它。

由此得到一条推论：**不是"聪明的做所有事"，而是"只有需要全局判断的才进主模型"**。主模型若被拉去做批量改文案，等于用最贵的资源干最便宜的活，还挤掉了它该留的上下文。

## 3. 调用形态

副模型不只以子代理形式出现。三种形态都能用，**换形态只影响上下文隔离与并行度，不影响谁定契约**。

| 形态 | 适用任务 | 权限 | 主要收益 |
|---|---|---|---|
| **子代理** | 单文件或单模块改动；需要"不知道实现"的独立视角；需要限定写范围 | 写白名单内文件，或纯只读 | 上下文隔离、权限可限、失败不污染主会话 |
| **独立会话** | 从零写一整块新模块（如 `src/profile-store.mjs`、`src/watchdog-helper.mjs`） | 交付 diff，由主模型合并 | 可以按小项目完整跑一轮，不必占用主模型上下文 |
| **批处理** | 同类输入的大批量产出：8 语言文案、翻译、模板、截图重拍 | 只产出文本或文件，不碰源码逻辑 | 吞吐高、可并行、成本低 |

选择顺序：**能批处理就不开子代理，能子代理就不开独立会话**。形态越轻，主模型的调度成本越低。

三种形态的共同点：输入都是"契约 + 可判定验收"，输出都是"diff + 命令输出 + 未解问题"。形态变了，这个接口不变。

## 4. 调度规则

| 规则 | 原因 |
|---|---|
| 同一时刻只允许一个写者 | 两个工同时改 `src/` 必冲突，且冲突后的 diff 无法归属到具体任务 |
| 写型任务 ≤ 400 行 diff | 超了就是没切好，拆开重派 |
| 审查必须盲 | 只给接口签名、不变量、需求，不给实现。给了实现，它会顺着实现写测试——这是自审最常见的伪装 |
| 平台执行不做结论 | 只带回退出码、日志尾部、栈；"这是平台差异还是设计缺陷"由主模型判 |
| 未解问题至少一条 | 留空视为未完成，不是"没问题" |

### 任务书五段式

```
目标：把 NpmBackend.activate 的目录交换改成可重试的三段式，Windows 上不再因句柄占用失败
可写：src/backends/npm.mjs、test/npm-backend.test.mjs
禁止：改 ALLOWED_TRANSITIONS；改错误码数值；改退出码契约；引入第三方依赖；删除或弱化已有断言
验收：npm test 全绿 + node --check src/backends/npm.mjs
返回：diff 摘要 / 命令输出尾部 / 未解问题（至少一条）
```

## 5. 模块分工

按"可委托度"分三档，不按文件大小分。

### A 档 · 主模型独占（副模型只读）

| 模块 | 关键点 |
|---|---|
| `src/orchestrator.mjs` | 状态机、回滚决策、取消边界（`applying` 之后不可取消） |
| `src/journal.mjs` | `ALLOWED_TRANSITIONS` 是协议，不是实现细节 |
| `src/plugin-gate.mjs` | 五种处置的判定顺序；`verify()` 必须留在 staging 阶段 |
| `src/errors.mjs` | `ERROR_SPECS` 与 `INTERNAL_TO_PUBLIC` 映射 |
| `src/backends/npm.mjs` 的 `activate` / `rollback` / 路径边界 | 跨平台风险最集中，见 §6.2 |
| `src/backends/electron-updater.mjs` | `delegated` 不能被当成本机已验证 |

### B 档 · 主模型定契约，副模型实现

| 模块 | 契约要点 | 验收方式 |
|---|---|---|
| `src/profile-store.mjs`（新增，P0-1） | `disable/enable/list` 三个方法，写 `cordis.patch.yml` 且保留 `restore.json` | fixture profile：disable 后 `--dump-config` 不含该行；enable 后恢复 |
| `src/watchdog-helper.mjs`（新增，P0-4） | 只接受 journal 路径、profile、port、timeout 四个参数 | kill 新进程 → 旧版本恢复；helper 崩溃 → `recover` 兜底 |
| `src/telemetry.mjs` 的 `HttpSink` | 固定端点、超时即丢弃、默认关闭 | 断网下更新不受影响；抓包无 PII |
| `src/i18n.mjs` | 新增 key 必须 8 个 locale 同步 | 缺 key 的 locale 测试直接失败 |
| `src/semver.mjs` | 补 alias / `workspace:` / 极端范围 | 表驱动用例，主模型审表 |
| `src/cli.mjs` | 退出码 0/1/2/3 是契约，不得变动 | 7 个 scenario 的退出码断言 |

`prototype.html`、`preview*.png` 重拍、README 英译、`.github/` 下模板与 workflow、`CHANGELOG.md`、`state-machine.svg` 同步。

## 6. 跨平台适配

### 6.1 归属判据

| 问题性质 | 归属 |
|---|---|
| 语义边界：能否原子、失败算不算失败、重试几次、降级到哪 | 主模型 |
| 机制落地：把决定写成代码 | 副模型（实现） |
| 目标平台是否真的这样 | 副模型（执行），主模型（判断） |

一句话：**平台差异归主模型，平台验证归副模型，平台结论归主模型。**

这条必须立住，因为开发机只有 Windows，macOS 行为本地验证不了。任何"我看代码应该没问题"的 macOS 结论都不作数，唯一裁判是 CI 和真机。

### 6.2 已确认的跨平台障碍

以下是从现有代码读出的，不是推测：

| # | 位置 | 问题 | 影响 | 归属 |
|---|---|---|---|---|
| C1 | `src/backends/npm.mjs:118` + `:36-41` | Windows 下用 `npm.cmd` 且 `shell: false` | Node 20.12+ 的安全修复后，`.cmd` 不经 shell 无法启动，**Windows 侧 npm 后端直接不可用** | 主模型定方案（解析真实 `npm-cli.js` 路径，或受控 `shell:true`），副模型实现 |
| C2 | `src/backends/npm.mjs:45,49` | `child.kill('SIGTERM')` | Windows 无信号语义，只杀 `npm.cmd` 本身，派生的 node 进程残留，后续 `rename` 必失败 | 主模型定 `killTree` 策略，副模型实现 |
| C3 | `src/backends/npm.mjs:404-409` | `rename(profile → .old)` 再 `rename(staged → profile)` | Windows 上目录被占用（dsh 运行中 / 杀软扫描 / handle 未释放）即 `EPERM`；跨卷 `EXDEV` | 主模型定"三段交换 + 退避重试 + 降级复制"协议，副模型实现 |
| C4 | `src/backends/npm.mjs:420-423` | 回滚时 `rename(profile → .failed).catch(()=>{})` 吞掉错误，紧接着 `rename(previous → profile)` | 第一次失败被静默，第二次必失败 → 回滚失败进安全模式。**"更新失败也回滚不了"的最短路径** | 主模型改语义（失败即中止上报，不吞异常），副模型实现 |
| C5 | `src/json-store.mjs:17,47` | 原子写靠 `rename` 覆盖 | Windows 上杀软/索引器持有句柄时偶发 `EPERM`/`EBUSY` | 副模型实现退避重试 |
| C6 | `src/lock.mjs:29,52` | `open(..., 'wx')` + 陈旧锁 `unlink` | Windows 上被占用时 `unlink` 失败；接管竞态窗口比 POSIX 更宽 | 主模型定 token 二次校验，副模型实现 |
| C7 | `src/backends/npm.mjs:471` | `cp(snapshot, profileDir, {recursive:true})` | 默认保留符号链接，Windows 建 symlink 需管理员/开发者模式；pnpm 结构必踩 | 主模型定 `dereference` 策略与 pnpm 支持范围，副模型实现 |
| C8 | 全项目 | 大小写不敏感文件系统（NTFS / 默认 APFS） | 仅大小写不同的 profile 名会互相覆盖 | 主模型定规范化规则，副模型实现 |
| C9 | 全项目 | Windows 路径长度 260 | `node_modules` 深层路径超限；含中文用户名的路径更早触发 | 主模型定启动前校验与提示，副模型实现 |
| C10 | `src/lock.mjs`、journal | `mode: 0o600` 在 Windows 无效 | 敏感文件权限不生效 | 主模型确认 journal 不含机密（当前成立），副模型文档化 |
| C11 | `$DSH_HOME` 解析 | 三平台默认位置不同（`%APPDATA%` / `~/Library/Application Support` / XDG） | 装完找不到 profile | 主模型定规则，副模型实现 `src/platform/paths.mjs` |
| C12 | 读写 yml/json | Windows 默认代码页与 BOM | `cordis.patch.yml` 被写入 BOM 后解析失败 | 副模型实现 UTF-8 无 BOM + 中文路径用例 |

## 7. 协作边界

### 副模型不得

- 改 `ALLOWED_TRANSITIONS`、改错误码数值、改退出码契约 0/1/2/3
- 删除或弱化已有断言
- 引入第三方依赖（零依赖是核心卖点）
- 改 `LICENSE` / 版本号 / 隐私声明
- 在未获授权时扩大改动范围（回修只改点名项）

### 主模型不得

- 把"跑起来看着对"当验收
- 把跨平台判断交给副模型（平台差异是设计问题，不是实现细节）
- 同时派多个写型任务
- 让副模型自己决定错误码或状态迁移

### 交接判定

同时满足才算交付：`npm test` 全绿 · `node --check` 通过 · 目标 scenario 退出码符合约定 · 目标平台 runner 通过 · 未解问题已列。

| 里程碑 | 内容 | 主 : 副 | 出口标准 |

| **M3 双平台** | W1 + W2 全量 | 5 : 5 | 四组合 runner 全绿 |

## 9. 公开发布时的契约红线

公开即承诺。以下变更从"随便改"升级为"必须发 major 并写迁移说明"：

- `UpdateBackend` 的 11 个方法签名
- `UpdateOrchestrator` 的 17 个状态名
- `UPD-*` 错误码及其阶段归属
- CLI 退出码 0/1/2/3
- `$DSH_HOME/updates/` 的磁盘布局与 journal 格式

仓库形态先保持**单包 + 子路径导出**，不过早拆 monorepo：

```
package.json  exports: { ".": "./src/index.mjs", "./backends/npm": "./src/backends/npm.mjs" }
```

`dependencies` 保持为空；Electron 相关放 `peerDependencies` 或 `optionalDependencies`。

## 附：三种调用形态的任务书模板

**子代理·实现型**

```
你是实现者。只改白名单内的文件，其他一律只读。
目标：<一句话>
契约：<签名 / 不变量 / 错误码 / 禁止事项>
可写：<文件列表>
验收：npm test 全绿 + node --check <文件>
返回：diff 摘要 / 命令输出尾部 / 未解问题（至少一条）
```

**子代理·审查型（盲）**

```
你是审查者。你没有实现代码，也不要读 src/ 下的实现。
需求：<功能描述>
接口：<签名>
不变量：<列表>
任务：按需求写边界测试，覆盖空值、超时、部分失败、重复调用、并发。
返回：测试文件 + 你认为实现方最可能搞错的三个点
```

**独立会话·整块模块**

```
按小项目完整做一轮，结束后交 diff 和一份 README 片段。
模块：<名称与职责>
对外接口：<签名>
不变量：<列表>
禁止：改动本模块以外的文件
返回：diff / 自测命令与输出 / 未解问题
```

**批处理**

```
输入：<文件或清单>
规则：<术语表 / 格式要求 / 禁止意译的专有名词>
输出：<目标文件>
要求：逐条对齐，不得合并或省略条目，产出后自检条数一致
```
